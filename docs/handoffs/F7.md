## Decisions made here

All of these sit within the approved specification; none needed a question.

- **E1, confirmed in both languages.** With the E1 lines of rows 2, 3 and 11, no single code point, no pair of D9's set and none of 100,000 seeded random strings folds differently a second time, under `ar` or `ckb`, in TypeScript or in the twin. A mutation run on the TypeScript fold showed that removing any one of the three lines makes the property tests fail.
- **Row 0 reads the text as received.** That is "before step 1" read literally, and both implementations read it so independently. Only ه directly followed by a ZWNJ is the legacy pair; a presentation-form heh, or a heh carrying a haraka or tatweel, before the ZWNJ folds to ه (`uni-0031`).
- **URLs (D3).**
  - The prefixes are compared in ASCII case only. After row 1's NFKC that is exact: no other character case-matches a prefix letter (the twin checked every code point).
  - The rule reads the text after row 1 deletes the invisible marks and before row 2 deletes tatweel, which is a letter. So a URL glued to a word by either is no URL (`url-0031`, `url-0032`).
- **Row 2's range** U+06D6–U+06ED holds three signs that are no marks (U+06DD, U+06DE ۞, U+06E9 ۩). They are deleted, as the PRD says, so they join their neighbours (`uni-0032`, `uni-0033`).
- **D4** turns U+20DD–U+20E4 into spaces as written, U+20E1 included, although it is a non-enclosing mark.
- **D5, read literally.** Two tags can touch: `#a_#b` folds to itself, as the tokens `#a_` and `#b`. `#_` is a tag, and `#a#b` folds to `#a b`.
- **`textNorm` checks the label even when there is nothing to fold**, in both languages. The twin already did; the TypeScript fold did not until a failing test and a fix in this build.
- **The `rows` of a computed case** are detected by `scripts/corpus/rows.py` from what each step changes. An anchor keeps its hand-written claims, and the detector must find each of them. Rows 0 and 11 are never claimed: row 0 is D-S1's, and row 11 only composes what the earlier rows produced.
- **The twin's layout** follows `contracts`. It reads `packages/text/data/` and `contracts`' `schemas/vocabulary.json` and `registries/unicode-15.1-unassigned.json` by their repository paths, so it is installed editable. It needs Python 3.13 (Unicode 15.1) and refuses any other Unicode version.
- **Build order:** `text` imports `contracts` from its `dist/`. turbo's `^build` orders the two in `make check`, and `text`'s tests build `contracts` themselves when its `dist/` is missing (`test/setup/contracts-dist.ts`).
- **Dependencies (E8):** `text` has no runtime dependency besides the workspace `contracts`. `zod` 4.6.5 is a development dependency, for the corpus schema, and has F2's screened row; the twin's tools have F1's rows. `docs/dependencies.md` is unchanged.
