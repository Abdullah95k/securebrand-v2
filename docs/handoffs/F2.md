## What it does now

`packages/contracts` 1.0.0 holds every message contract of the platform for TypeScript (`contracts`) and Python (`listening-contracts`, imported as `listening_contracts`):

- the 19 schema ids, each written once in Zod 4 and built strict and tolerant, with their JSON Schema export and the generated Pydantic v2 models;
- `validate()` with the cross-field and registry checks;
- the key and id helpers with golden vectors that both languages reproduce byte for byte;
- the registries the SDK enforces, as JSON data both languages read;
- the closed lists;
- the n8n signing helper.

`fixtures/contracts/` holds 727 contract fixtures (284 valid, 421 invalid, 22 tolerant, 94 of them PRD 6.2 examples rewritten under the ADRs) and 11 golden files.

Open first:

- `packages/contracts/README.md` (with runnable examples) and `docs/contracts/VERSIONING.md`;
- `packages/contracts/src/index.ts` and `src/validate.ts`, and their Python twins `python/listening_contracts/__init__.py` and `validate.py`;
- `fixtures/contracts/README.md`.

## Decisions made here

Points the plan left to the build, each settled inside the plan and the ADRs it names. Two needed the orchestrator, who decided Q17 and Q18 on 25 Oct 2026 (below).

- **The government rule's input (Q11, F-50).** No message field carries the client's type, so the producer passes it to `validate()`: `clientType` in TypeScript, `client_type` in Python. Producer mode fails closed on a client or account-manager alert without it (`no_client_type`, at the root path), following CONVENTIONS v1.1 L84's fail-closed rule. This supersedes an earlier note to add a schema field.
- **A job's queue (ADR-0012).** The producer-table row and the required kind fields depend on the queue, so producer mode refuses a job validated without one (`no_queue`). With a queue, both modes check the row.
- **Where refusals are reported.**
  - A decision-row refusal (no row, or provenance required or refused) is reported at `["producer", "service"]`.
  - A shape error's `code` and `message` come from Zod or Pydantic and differ between the languages. Its path is the same in both, except under the six plain unions (registry.decisions, poster.profiles, items.analysis, raw.items, n8n.alert `details`, a push job's `body`), where the path sets may differ as `golden/issue-paths.json` records. The package's own rules use the same codes and paths in both.
- **Open maps (F-34).** The snake_case key rule of `reactions_by_type`, `public_metrics` and `language_share` lives in `validate()`, because pyright refuses the patterned dict keys the model generator renders. Applying the rule to the last two (X's `retweet_count`, the index's `ara`) is F2's choice.
- **The DLQ's paths.** The schema file is `schemas/dlq/v1.json`, the Python module `dlq_v1`, and the fixture directory `fixtures/contracts/dlq/v1/`.
- **The dead-letter copy rule (D-1 and D-12, decided by the orchestrator on 25 Oct 2026; review findings 1 and 4).** A record copies its original's `provenance` under the original's own type: the signal provenance, with a nullable route, for an author-, source- or client-scope deletion, and the data provenance otherwise. It copies `retention_class` only when the original has a valid one; null, absent and unknown classes are alike in both languages. When the original's provenance fails its own type, the record carries neither (plan L397). The record's `provenance` is typed as the signal provenance, and `validate()` binds it to the original's own type. The producer's strict type decides whether a copy is due; the validating mode's type judges a copy made, so a consumer tolerates a provenance field that a newer package adds. The rule compares structurally and never throws.
- **The Unicode version (D-2, decided by the orchestrator on 25 Oct 2026; review finding 7).** NFC and lower case are those of Unicode 15.1.0 in both languages. A code point 15.1 leaves unassigned (`registries/unicode-15.1-unassigned.json`) passes through `nfc` and `lowerCase` (`lower_case`) unchanged and is never refused; the helpers normalise and lower-case the runs of text between such code points. A runtime below Unicode 15.1 cannot import the package (`unicode_version`). The three lower-case calls on free text (`query_key`'s forms, a handle's candidate key and a URL's host) use `lowerCase`; the lower-casing of ASCII-checked values (a Telegram username, a URL scheme, a registrable domain) is unchanged. Known residual, recorded in VERSIONING.md and not fixed: a capital sigma next to U+0295 or U+1171E lower-cases differently in Node 24 and Python 3.13.
- **Provenance on the qualifier's `tier_change` and `dormant` (D-3, decided by the orchestrator on 25 Oct 2026; review finding 8).** Their decision row is bound to `rule_hit` (`rule_hits` in `registries/decision-producers.json`, and `rule_hit` in the decision query of both languages): rules 6 and 10 require provenance, rule 9 refuses it, a rule-3 `dormant` accepts either, and any other `rule_hit` has no row (`decision_not_allowed`). VERSIONING.md's "Decisions with and without provenance (F-14)" states it.
- **Issue paths (D-4, decided by the orchestrator on 25 Oct 2026; review finding 10).** Python reports a shape error at the path Zod gives it. Under each of the 13 discriminated unions (each a `oneOf` of the exported schema, whose branch titles are the generated classes' names) it keeps only the branch the input's tag selects, compared with its JSON type; a tag that selects no branch, or none at all, gives one issue at the discriminator (`union_tag_invalid`, `union_tag_not_found`), and a value that is no object one issue at the union. It drops every step that names no key of the message, except a missing or an unknown field's name, and the errors of a nullable's or an optional's other alternative (`none_required`, `missing_sentinel_error`) when the field has another error, and lists each path and code once. TypeScript's route-level `health_change` rule takes an absent `fallback` or `scope` as null, as Python does. Under the six plain unions the path sets may still differ (the residual above): over the 334 such runs, 285 agree, Python lists more branches in 45, and in the 4 runs of the two finding-6 fixtures (`poster.profiles/v1/invalid/public-account-zero.json`, `raw.items/v1/invalid/context-partial-one.json`) TypeScript lists more. `fixtures/contracts/golden/issue-paths.json`, written by `scripts/issue-paths.ts` (`pnpm --filter contracts gen:issue-paths`) after `gen:fixtures`, holds TypeScript's path set for all 926 runs of the invalid and tolerant fixtures; both suites assert equality on the other 592 and, under the plain unions, the verdict and the expected path. Hand-checked sample (producer mode, golden against `expected.json`): `deletions/v1/invalid/admin-platform-sync.json` (scope `client`) gives `[["reason"]]`, where Python listed the item, author and source branches too before the fix; `dlq/v1/invalid/null-route-not-a-deletion.json` gives `[["provenance"], ["retention_class"]]` (the copy rule refuses both); `crawl.policies/v1/invalid/hyphenated-signal.json` gives `[["usage_signals", "ai-input"], ["usage_signals", "ai_input"]]` (an unknown key and a missing one); `job/v1/invalid/analyze-with-item.json` gives `[["item"]]`; `items.normalized/v1/invalid/key-not-the-helpers.json` gives `[["idempotency_key"], ["item_id"]]`; `n8n.card/v1/invalid/card-id-not-the-subjects.json` gives `[["card_id"], ["idempotency_key"]]`; `source.events/v1/invalid/added-with-previous.json` gives `[["previous"]]`; and, under plain unions, `n8n.alert/v1/invalid/engagement-spike-text-metric.json` lists every `details` branch with `["details", "metrics", "engagement"]` among them, and `raw.items/v1/invalid/comment-without-author-ref.json` both top-level branches with `["envelope", "author_ref"]` among them. Each holds the expected path.
- **Registry reads in consumer mode (D-9, decided by the orchestrator on 25 Oct 2026; review note 11).** A `jobs.completed/v1` report's X fields and its queue's partition-key field are checked in consumer mode only for a service the package knows, and always in producer mode. - **Python's validation semantics.**
  - Models validate with `strict=True`, and optional non-null fields use Pydantic's `MISSING` sentinel, so `null` is refused as in Zod.
  - JSON numbers follow JavaScript: an integral float is an integer, and a non-finite number is refused.
  - Every string and object key is well-formed Unicode, in both languages: `validate()` refuses a lone surrogate before the schema, with `not_unicode` at its path (review finding 5).
  - A constant keeps its JSON type. Pydantic matches a literal by equality even in strict mode (0 for `false`, `true` for 1), so `validate()` compares the parsed message's JSON types with the message sent and refuses a swap with `literal_error` at its path, as Zod and the JSON Schema `const` do (review finding 6).
  - Error paths drop Pydantic's branch labels and keep only the selected branch of a discriminated union (D-4).
- **The `/code-review` fixes (F-49 and parity).**
  - An idempotency key holds no dot, the signed string's separator.
  - `verify` throws `bad_now` or `bad_tolerance` on a NaN, infinite or negative clock or tolerance.
  - Times are taken in the years 0001 to 9999 in both languages.
  - Canonical JSON refuses lone surrogates with `not_unicode`.
- **Entry points.** Besides the root, the package exports `./schemas` (Zod schemas by id and mode), `./keys` and `./registries`, compiled to `dist/`. The Python root re-exports the same API.
