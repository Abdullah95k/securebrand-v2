## Operations

- CI jobs and durations: see "CI" above; `check` brings the stack up on every pull request.
- `make up` fails to pull the Redpanda mirror: the GHCR package is private until the user makes it public (cloud sessions have no GitHub credentials); `docker login ghcr.io` or `IMAGE_REGISTRY=upstream make up` meanwhile. CI pulls it with `GITHUB_TOKEN`.
- Docker Hub answers 429 on shared addresses: only the mirror workflow pulls from it; if runner pulls ever hit 429, the user adds the `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` secrets.
- Cloud sessions: start dockerd first (`docs/orchestration/README.md`); the scripts pick Node 24.21.0 from nvm (`/opt/nvm`, `~/.nvm` or `NVM_DIR`) when the default node differs; `make bootstrap` installs it, makes it nvm's default and updates uv to 0.12.23. Every command a session runs starts a new shell on `/opt/node22` (the container loads nvm lazily), so a pnpm command typed by hand needs `nvm use 24.21.0 >/dev/null &&` in front (`make doctor` names the switch); `make new-service NAME=<name>` and the other make targets need nothing.
- A port is taken on a developer machine: the ports are fixed (`stack/README.md`); stop the other process.
- The mirror workflow fails with "<mirror>:<tag> holds sha256:..., but <upstream>:<tag> is sha256:...": the upstream was retagged, or a branch copied from a wrong upstream. Check which image is right, correct `stack/versions.env`, and run the workflow on main (Actions, Mirror images, Run workflow on main), which replaces the tag.
- An S3 put to a new bucket answers 500 "We encountered an internal error": SeaweedFS is out of volume slots (seven per bucket, 200 in all). Remove stale test buckets (`make ns-clean` with `TEST_NAMESPACE=<namespace>`) or run `make down`.
