### Reproduction of finding 1

The two tests, added to `tools/repo-checks/test/unit/` with stop-gate.test.ts's `beforeEach`, `arm`, `stop` and `stubRuns`:

```ts
it("keeps the exemption when the code it covered is committed unchanged", () => {
  arm();
  repo.write("services/a/index.ts", "export const changed = 1;\n");
  repo.write("docs/issues/X-1.md", "# Issue · X-1\n");
  expect(stop().code).toBe(0); // "Stopped with a proposal or issue filed in this session"
  repo.git("add", "-A");
  repo.git("commit", "-q", "-m", "X: the failing test and its issue");
  expect(stop().code).toBe(0); // 8674199: 2, "make check failed (round 1 of 3)"
});

it("does not rerun green checks when the code they passed on is committed unchanged", () => {
  arm();
  repo.write("services/a/index.ts", "export const changed = 1;\n");
  expect(stop("s1", 0).code).toBe(0);
  repo.git("add", "-A");
  repo.git("commit", "-q", "-m", "X: work");
  expect(stop("s1", 0).code).toBe(0);
  expect(stubRuns()).toBe(1); // 8674199: 2
});
```

Appended to a copy of stop-gate.test.ts and run with `pnpm exec vitest run` at 8674199: "Tests 2 failed | 27 passed (29)", the two being these, with "expected 2 to be +0" (the hook's stderr, printed by the probe: "make check failed (round 1 of 3). Fix the cause; never weaken or skip a test to pass. ...") and "expected 2 to be 1". The same file on origin/main's hooks: both pass (its 16 failures there are the lane's own W2 tests).

Why it matters: the kit's local flow is "a failing test, `docs/issues/$0-<n>.md` from the template, then stop" (`build-session/SKILL.md:34`), with no commit before the stop. When the developer then asks Claude to commit, the gate sends it back up to three times to fix a test that fails by design, and its message tells it to file under `docs/issues/` and stop, which invites a second issue for the same problem. Orchestrated sessions, which commit and push before they stop, do not meet it. A fingerprint that does not move with the index or HEAD fixes both, for example a hash of the content of every tracked and untracked file under the same pathspecs, as `:80-82` already does for the untracked ones.
