# Review · F2 Contracts package

Reviewer session (fresh, cloud container) · 2026-10-25 · diff reviewed: `origin/main` 8ac7249..`sb/F2` 71995e6 (20 commits, 990 files, 104,249 lines added)

Verdict: needs fixes: 2 blockers, 8 should-fix

F2 has no PRD: its acceptance criteria are rows A1 to A38 of the approved plan (`docs/plans/F2.md` L20 to L57), which stand in for "PRD 13" below. Much of the package holds. Both suites pass in both languages, also with no network, and `make check` passes; the policy gate fails only because this review did not exist yet. All 384 golden vectors reproduce byte for byte in both languages and recompute from the specification with standard libraries. Every closed list and registry equals the ADR or plan line that names it, apart from one registry row (finding 8), and service names and vendors are patterned strings checked in producer mode (Q1). ADR-0003's provenance rules hold on every data and control schema, apart from the dead-letter record (finding 1) and that row. The five new dependencies are listed truly and clear the vendor screen, the diff stays inside the brief's scope, and Q1 to Q18 are built as decided, with only Q2 and Q10's rule credited to the user. `validate()` gives the same verdict in both languages on all 727 fixtures in both modes, and the package's own rule codes agree on every refused fixture.

Two findings block. The dead-letter record cannot hold a valid author-, client- or source-scope deletion whose reason involves no fetch: its top-level `provenance` is the strict data type, and `validate()` refuses both copying the deletion's provenance and leaving it out, so the fifth failed attempt of retention-purger or deletion-propagator has no record the SDK can send (finding 1). A14's test "form order and NFC variants give one key" compares two golden vectors neither of which holds a decomposed form, and a copy of the package with NFC removed from `query_key` gives the same test results in both languages as the package itself (finding 2). Eight findings are should-fix:

- poster.profiles lets a resolved individual whose `public_account` is null carry a handle, name and URL (3);
- the dead-letter rule throws in TypeScript, and splits the languages, on originals whose own provenance or class is malformed (4);
- on inputs no fixture covers, the languages give different verdicts on lone surrogates (5), on 0 and 1 in place of false and true in constants (6), and on keys and hashes of text holding code points newer than Unicode 15.1, whose plan-named test does not exist (7);
- tier_change and dormant accept provenance or its absence against the plan's row (8);
- two PRD examples keep values that Q7, ADR-0037 and ADR-0044 rule out (9);
- Python's issue paths list every union branch, against the handoff's promise of the same paths (10).

Notes 11 to 22 record narrower gaps and documentation errors.
