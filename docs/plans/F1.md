**Registry strategy (Q2).** Local-stack images are referenced through `IMAGE_REGISTRY` (default: the GHCR mirror `ghcr.io/<owner>/securebrand-v2/<image>:<tag>`, filled by `.github/workflows/mirror-images.yml` with `docker buildx imagetools create` from the pinned upstream tags; override `IMAGE_REGISTRY=upstream` to pull from Docker Hub, `docker.redpanda.com` and `public.ecr.aws` directly). Supabase images come from `public.ecr.aws/supabase/*` through the CLI and need no mirror. Service Dockerfiles take their base image from `public.ecr.aws/docker/library/node:24-bookworm-slim` and `public.ecr.aws/docker/library/python:3.13-slim`.

**Supabase local (Q3).** `supabase start` with `-x studio,imgproxy,mailpit,edge-runtime,logflare,vector,supavisor,realtime,storage-api` by default (db, kong, auth, rest stay); `SUPABASE_FULL=1 make up` starts everything. `project_id = securebrand` in `supabase/config.toml`; ports 54321 (API) and 54322 (DB).

**Layout.** Root `compose.yaml` and `stack/` (versions, ClickHouse `config.d` and `users.d`, SeaweedFS `s3.json` with fixed development credentials, README). pnpm workspaces: `services/*`, `packages/*`, `tools/*`, `tools/probes/*`, `tests/e2e/*`; package names are unscoped and equal to the directory name so `pnpm --filter <service>` works as CLAUDE.md says (Q11). Python projects are independent uv projects (own `pyproject.toml`, `uv.lock`, `.venv`), sharing `ruff.toml`, `.python-version` and `uv.toml` from the root and depending on `py/listening_sdk` by path (Q7). Reserved folders get a README only: `tests/e2e/` (E1), `tools/gates/` (E2), `tools/probes/` (probe sessions), `fixtures/` (probe rules), `infra/` (I1).

**Ports and variable names** (names only; the handoff repeats them): Redpanda Kafka `localhost:19092` (internal `redpanda:9092`), admin 9644, schema registry 18081, HTTP proxy 18082 → `KAFKA_BROKERS`; ClickHouse HTTP 8123, native 9000 → `CLICKHOUSE_URL`, `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD` (fixed development value); SeaweedFS S3 8333, master 9333, filer 8888 → `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` (fixed development values), `S3_BUCKET=listening-local`, `S3_REGION`, `S3_FORCE_PATH_STYLE=true`; Supabase → `SUPABASE_URL`, `SUPABASE_DB_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` read live from `supabase status -o env` by `scripts/stack-env.sh`, never written to a file. `make test`, `make check`, `make e2e` and `make smoke` evaluate `scripts/stack-env.sh` and `scripts/test-namespace.sh` before running.

**Namespaces.** `TEST_NAMESPACE` → `TEST_TOPIC_PREFIX=<ns>.`, `TEST_PG_SCHEMA=test_<ns>`, `TEST_PG_DATABASE=test_<ns>`, `TEST_CH_DATABASE=test_<ns>`, `TEST_S3_BUCKET=test-<ns with _ as ->`. Tests create what they need under these names and `make ns-clean` removes them. The SDK (F4, F6) applies the prefix in test mode; F1 only defines and exports the contract.

**CI** (`.github/workflows/ci.yml`, on `pull_request` and on `push` to `main`, `concurrency` per ref, read-only token, timeouts):
1. `check`: `ubuntu-24.04`, checkout with full history, toolchain from the pins (setup-node from `.node-version`, pnpm from `packageManager`, uv pinned, Python from `.python-version`, Supabase CLI from the devDependency), `pnpm install --frozen-lockfile`, `make up` (`CI=1` → minimal Supabase, mirror images), `make check`, `make smoke`, `make down`; uploads `.build-state/last-check.log` on failure.
2. `policy` (pull requests): `scripts/policy/check-contract-paths.sh` with the pull request labels, `check-handoff-review.sh` with the head branch, `check-dependencies.sh` against the merge base, `scripts/check-fixtures.sh`. Each is also `make policy` locally.
3. `template-smoke`: `pnpm new:service demo && make check` and the Python twin, word for word the G0 check.
`mirror-images.yml`: `workflow_dispatch` and `push` to `main` touching `stack/versions.env`; `packages: write`; logs in to GHCR with `GITHUB_TOKEN` and to Docker Hub with `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` when present; copies each pinned tag. `dependabot.yml` (Q10): weekly, grouped, ecosystems npm, uv, docker, github-actions.

**Policy scripts' scope.** `check-handoff-review.sh` reads the session ID from the head branch `sb/<ID>`; on `sb/CC-<proposal>` it requires the applied proposal instead; on any other branch it skips with a notice (Dependabot and hotfix branches are the user's to merge). `check-contract-paths.sh` is label-only, as the brief says (Q5). `check-dependencies.sh` enforces runtime dependencies and images; the register itself also lists the tools (Q12).
