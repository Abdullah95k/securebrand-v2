## Technical decisions taken in this plan (no question needed; the orchestrator may overrule any of them)

| # | Decision | Why (source) |
|---|---|---|
| T1 | One schema, `public`. Every closed list is `text` with a `CHECK` naming F2's exact values, never a Postgres enum type. | VERSIONING.md: closed lists grow only by a new contract version, which is a reviewed migration either way; a CHECK can be replaced in one transaction, an enum value cannot be removed. |
| T2 | `uuid` for `source_id`, `client_id`, `keyword_id`, `item_id`, `post_item_id` (ADR-0006 "F3 and F8 type the id columns `uuid`"); ULIDs (`decision_id`, `message_id`, `job_id`, `run_id`, `request_id`, `story_id`, `reservation_id`, `review_id`, `alert_id`) are `text` with F2's ULID pattern as a CHECK, because a ULID is not a UUID string and F2 renders it in Crockford base32. | ADR-0006, ADR-0002, F2 `patterns.json` `ulid`. |
| T3 | Times `timestamptz`; hashes `text` with the `sha256Hex` pattern (bare 64 lower-case hex, ADR-0036); `author_ref` the same pattern (ADR-0010); `content_hash` the `prefixedSha256` pattern (ADR-0009); platform ids `text`, never numbers (F2 `platformId()`). | F2 `patterns.json`; ADR-0006, 0009, 0010, 0036. |

## What the migrations create

Each table below: key, columns (type; constraint), indexes, the one writer per row or column (detailed in TABLE-OWNERS.md), the RLS class, and the source. RLS classes: **S** service only (RLS on, no policy for `anon` or `authenticated`, so only the service role reads and writes); **C** client-facing (RLS on, read-only select policy for a client user limited to their clients' rows, Question 1); **A** append-only (S plus the T7 trigger).
