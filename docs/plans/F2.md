# Plan · F2 Contracts package

Brief: build-plan/sessions/F2-contracts-package.md · PRD: none (foundation session; the requirements are the brief, CONVENTIONS v1.1 in full, the 55 ADRs that apply to F2, check 2 of G0 in `build-plan/GATES.md` and the definition of done in `build-plan/README.md`) · Approved by: pending (orchestrator)

## Context the plan rests on

- **What was read, in the brief's order.** The brief; CONVENTIONS v1.1, the whole file; the 55 ADRs that apply to F2 (ADR-0001 to ADR-0014, ADR-0016 to ADR-0018, ADR-0020 to ADR-0027, ADR-0030 to ADR-0046, ADR-0051 to ADR-0054, ADR-0057, ADR-0059, ADR-0060, ADR-0064, ADR-0065, ADR-0067 to ADR-0070: 45 name F2 in "Applies to" or "Sessions that must read this", as `docs/handoffs/D2.md` L115 lists them, and ten more apply to "all"); `docs/decisions/DEFERRED.md`, whose rows name F2 nowhere (checked: no row names F2; the rows that touch an F2 shape are listed under "Contracts"); `docs/handoffs/D2.md` and `docs/handoffs/F1.md` (and `docs/handoffs/F1b.md`, for the contract guard on `sb/F2`); `docs/contracts/INVENTORY.md`, background only (ADR-0070); and the section 6.2 example of all 86 PRDs. ADR-0049, ADR-0050 and ADR-0066 were also read for the values of `lifecycle`, `push_covered`, the flags and the owned-property `add`, which `source.events` and `registry.decisions` carry. Subagents read the rest of the inventory and collected the closed value lists that ADRs ask F2 to fix without listing them; every list below cites its source.
- **Precedence.** An ADR wins over every PRD (ADR-0001), and where two PRD examples disagree the ADR decides, never a majority. Where no ADR touches a field, the producer's PRD 6.2 example stands, with ADR-0070's single spelling. INVENTORY and CONFLICTS are D1's record of the PRDs as written, background only (ADR-0070, CONVENTIONS v1.1 L5). Every PRD example below is read as its ADRs reshape it: flat routing fields fold into `provenance` (ADR-0003), the type is `kind` and never `reason` (ADR-0011), every id follows ADR-0006. Where an ADR asks F2 to close a list or declare fields and no ADR or PRD token gives a value, or the PRDs spell one value several ways, the plan drafts the value with its source and asks (Q8); nothing is frozen on a guess.
- **What F2 builds.** `packages/contracts` v1.0.0: Zod 4 schemas for every topic, job and payload listed under "Contracts", exported as JSON Schema draft 2020-12 with Zod's own exporter, and Pydantic v2 models generated from those JSON Schemas (ADR-0030); the key and id helpers with TypeScript and Python twins and golden vectors (ADR-0006, ADR-0007, ADR-0009, ADR-0010, ADR-0035, ADR-0036, ADR-0044); the registries the SDK enforces (the producer table, ADR-0012; the partition-key record, ADR-0004; each producer's `context` keys, ADR-0005; each producer's visibility, ADR-0053); valid and invalid fixtures under `fixtures/contracts/`; conformance suites in both languages; `docs/contracts/VERSIONING.md` (ADR-0002).
- **What F2 does not build.** Tables (F3: `supabase/migrations`, `TABLE-OWNERS.md`), ClickHouse (F8), the SDK runtime that stamps, validates, partitions and enforces (F4, F6, F5), normalize-item's mappers (each producer's session with C4, ADR-0008), and the HTTP APIs of single services: quota-governor's request and answer and the SDK `report` (C1, F5), lang-dialect-id's call (C3), raw-archiver's replay, read and media endpoints (C2), the admin API's request endpoints and the client re-run and refresh endpoints of backfill-orchestrator and comment-decay-scheduler (D3, C10, C11). No ADR assigns those to F2, and `backfill-orchestrator §6.1` reads "the client re-run endpoint", an HTTP call. The one HTTP payload F2 types is n8n's (ADR-0067).
- **Lane.** The work runs on `sb/F2`, which `.claude/hooks/guard-contracts.sh` lets write `packages/contracts` (F1b); the pull request carries the `contract-change` label, which the orchestrator applies (`docs/orchestration/README.md`). `packages/contracts` is a pnpm workspace through the `packages/*` glob, and a `pyproject.toml` in the same folder gets the Python steps of `make check`; Python consumers depend on it through `[tool.uv.sources] … = { path = "../../packages/contracts", editable = true }`; `fixtures/contracts/` needs no per-file README entry but is scanned for tokens (`docs/handoffs/F1.md`, "For the sessions that depend on this").
- **Who reads F2's handoff first.** F4 and F6 (they stamp, validate and enforce what F2 declares), F8 (column names follow the messages), G0 (check 2), then every service through the SDK.

### Message metadata and provenance (every topic)

- Every message: `schema` (`<topic>/v<n>`, a constant per schema), `message_id`, `produced_at`, `producer {service, version, job_id}` (ADR-0002). `producer.job_id` is the ULID of the job behind the message, a receiver's receipt ULID for jobless records, never a composite or null (ADR-0006).
- Data messages (`raw.items`, `items.normalized`, `item.hits`, `discovery.hits`, `poster.profiles`, `item.metrics`, `items.analysis`, `article.urls`, `search.results`, `deletions`, `news.dedup`, `crawl.policies`, and `registry.decisions` that derive from a fetch) carry `provenance {route, vendor, service, fetched_at}` and a top-level `retention_class` (ADR-0003). `provenance.service` is the service that fetched; `producer.service` the one that emitted.
- Control messages (`job/v1`, `jobs.completed`, `source.events`) carry `producer` only and refuse `provenance` (ADR-0003).
- Exceptions: an author-, source- or client-scope `deletions` message carries the signal's provenance and no `retention_class`; a `registry.decisions` message entered by a person carries `requested_by` and no provenance (ADR-0003).
- Flat `route`, `vendor`, `service`, `fetched_at`, `item_fetched_at`, `found_at` as fetch time, `observed_at` as fetch time and `schema_version` in PRD examples give way to these fields (ADR-0002, ADR-0003).

### raw.items/v1

- Shape: one nested `{envelope, payload}` message for every producer; `payload` is the platform record as returned, minus identities, with `includes` and other response parts inside it; a news article is an extract by rule (ADR-0005, ADR-0010).
- Envelope, always: the metadata above; `platform`, `kind` (record kind), `provenance`, `retention_class`, `client_ids`, `job_id`, `attempt`, `job_kind`, `api_version`, `raw_ref` (ADR-0005, ADR-0003). The SDK stamps `retention_class` from the source row, else the route and platform default (ADR-0005).
- Envelope, by condition (ADR-0005, ADR-0009, ADR-0004): `source_id`, or `candidate_key` for a record about a candidate not yet a source (a resolver's `profile`); `platform_id` and `idempotency_key` for the five content kinds; `parent_id` and `root_id` on a `comment`, the parent's and the post's `item_id`, stamped from the job's `post_ref` with the key helper; on push and stream records a `job_id` made at receipt with `attempt = 1` and the delivery id in `context`.
- Archive-only kinds carry a defined key instead of `idempotency_key`: ADR-0005 fixes `search_response` as the rule's `source_id` plus the request time (`provenance.fetched_at`); F2 defines the other three in the same way: `profile` is `candidate_key` (or `source_id` for a refresh) plus `provenance.fetched_at`; `reaction` is `source_id` plus `platform_id` (the event's id, `li-notification-receiver §9`); `metrics` is `context.item_key` (the observed item's `idempotency_key`) plus `provenance.fetched_at` (ADR-0034).
- Envelope, optional: `context`, typed per producer (the table below), and `redacted_fields`, the payload paths an adapter removed or replaced, on any record (ADR-0005, ADR-0009).
- Discriminated by `kind`: a content kind requires `platform_id` and `idempotency_key`; `comment` requires `parent_id` and `root_id`; `profile` requires `candidate_key` or `source_id`, never both (ADR-0005). ### URL normalisation (ADR-0036; the rules are Q9's)

Recommended: one function for every news finder, the extractor and the router. Parse as an absolute URL, resolving a relative one against the base the caller gives (`news-feed-poller §5.2 L55`); lower-case the scheme and the host, the host in its ASCII (punycode) form; drop the default port, the fragment, an empty query and the tracking parameters `utm_*`, `fbclid`, `gclid` (`news-feed-poller §5.2 L55`, `news-sitemap-poller §5.2 L59`); sort the remaining parameters by name then value, keeping repeats; percent-encode path and query as UTF-8 of NFC with uppercase hex, decoding unreserved characters (the "one form" `news-dedup §5.3 L64` gives Arabic slugs); keep the scheme, `www.` and a trailing slash, which can name different pages. `url_hash` is hex SHA-256 of the result's UTF-8. news-dedup's stricter story key (https, no `www.`, no trailing slash) stays inside news-dedup, and search-hit-router's platform matching rules (`m.`, `mobile.`, `twitter.com` read as `x.com`, `§5.3 L70`) stay its routing logic; neither is `url_hash`.

### query_key (ADR-0044; the rule is Q10's)

Recommended: `query_key` is hex SHA-256 of the RFC 8785 canonical JSON of `{"context_terms": [...], "forms": [...]}`, each array the texts as saved (handles keep `@`, hashtags keep `#`, `keyword-matcher §5.3 L56`), each text in NFC and lower case, deduplicated and sorted by code point. Exclusions, `purpose`, `priority`, `platforms` and the client stay out (exclusions never enter a shared query, ADR-0044). The helper takes the two lists as arguments and calls no folding service, so identical saves give one key in both languages.

### Rows of DEFERRED.md that touch an F2 shape

No row names F2. These rows will add or fill fields later, each an additive change within the version under ADR-0002 and Q1: OCR and transcript text as a second analysis input (A4, ADR-0023); filling X stream-gap parts older than 7 days, reported `gap_unfilled` in v1 (X5, ADR-0064); the minimum language sample below which `lang_share` is null (C9, ADR-0033: a setting, no field change); a per-article `disqus_identifier` from the extractor (N6, ADR-0040: an optional field if chosen); the new amber reader of clients' own Facebook Pages and Instagram accounts (a new service name and its `context` keys, Q1); counsel's answer on listing Instagram creator accounts (ADR-0010: a change to the marks of Q7, not to the field).

## Risks (PRD 12) and their tests

F2 has no PRD section 12; these are the package's risks.

| Risk | Covered by |
|---|---|
| A Zod refinement does not survive the export, so TypeScript and Python validate differently | Cross-field rules are discriminated unions where possible; the rest live in `validate.ts` and `validate.py`; A4 runs every valid and invalid fixture in both languages, so a divergence fails the build |
| datamodel-code-generator renders a union, a constant or `additionalProperties` differently from Zod, or produces models pyright strict rejects | A3 (fresh generation equals the committed models), A4, and `make check`'s pyright step over the generated tree; a construct the generator cannot render is rewritten in the Zod source, never patched in the generated files |
| Node's ICU and Python's `unicodedata` implement different Unicode versions, so NFC differs on a recent character | Golden vectors with Arabic presentation forms, Sorani letters, combining marks, emoji with skin tones and ZWJ sequences (A8); a failure names the code point |
| RFC 8785 number rendering differs between the two libraries | `canonical-json.test.ts` and its twin over integers, negative zero, exponents and long decimals (A8); hashed structures in the contracts hold strings and integers only |
| A closed list frozen now misses a value a later session needs | Every list cites its source and the rewritten PRD examples validate (A6, A23); a later value goes through `/contract-change`, under the growth rule Q1 settles |
| A producer's `context` key or a kind field was missed | A6 rewrites all 86 PRD examples into fixtures; a gap found later is a proposal, additive within the version (ADR-0002) |
| The Instagram key depends on state (the id map) | The helper is a pure function over a lookup; vectors cover both branches and the later Graph read of a vendor-only post (A8) |
| A helper reads a secret or the clock | Every helper takes its inputs as arguments; `author-ref.test.ts` refuses an empty key; no test sets environment variables |

| Generated artefacts edited by hand | A2 and A3 compare with a fresh export and generation |
| The package version drifts between languages | A33 |
| A fixture change makes `make check` run every workspace (F1's rule for `fixtures/`) | Expected on this lane; noted in the handoff for the services that follow |
